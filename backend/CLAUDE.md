# backend/CLAUDE.md

Правила для кода FastAPI-бэкенда. Дополняют корневой `CLAUDE.md` (принципы кода, безопасность, работа с тикетами); при противоречии побеждает корневой. Основа — гайд «FastAPI Best Practices for AI Agents» в том виде, в каком он адаптирован в проекте GoCastMVP; что не зависит от выбора базы — перенесено, остальное ждёт редизайна.

**Правила описывают новый код** — и песочницу (`sandbox/`, #39). Единственное исключение — её швы `paths.use_run` и `clock.use`: один переключатель базы и часов на процесс (корневой `CLAUDE.md`, «Песочница»). Сборщик приложения — `main.py` (#38).

**Модули** лежат прямо в `backend/`, имена — из `GLOSSARY.md`: `companies`, `research`, `refusals`, `conversations`, `delivery`, `overview`. Общее ядро без бизнес-логики — `backend/core/` (не `platform`: это модуль стандартной библиотеки). Зависимости идут в одну сторону: `companies` → `research` → `conversations` → `delivery` → `overview`; `refusals` зовут все. Состав и причины — #4.

**База — одна SQLite без прогонов** (ADR 0002): `backend/data/state.db`, схема — Alembic, доступ — синхронный `sqlite3` (ADR 0004). Разделы «База данных», «Async», «Миграции» ниже.

**Настройки оператора — в базе** (ADR 0003): модуль сам описывает свои настройки и умолчания и отдаёт их своим API, `core` только хранит. Отдельного модуля настроек нет.

## Версии

Python 3.13 · FastAPI ≥ 0.141 · Pydantic ≥ 2 · pydantic-settings ≥ 2.15 · LangChain ≥ 1.3 · httpx ≥ 0.28 · pytest ≥ 8.

## Структура модуля

Код раскладывается по модулям предметной области, а не по типам файлов:

| Файл | Что внутри |
|---|---|
| `api.py` | роутер FastAPI — только HTTP |
| `dependencies.py` | зависимости роутов: загрузка и проверка объекта из пути, сборка сервиса |
| `service.py` | класс сервиса модуля — бизнес-операции и транзакция |
| `repository.py` | класс репозитория — SQL к своим таблицам |
| `schemas.py` | Pydantic-схемы запросов и ответов |
| `exceptions.py` | доменные исключения модуля (своих нет — файла нет) |
| `domain.py` | чистые функции без ввода-вывода, только где домен богатый (гейты, скоринг, разбор страниц) |
| `public.py` | фасад для других модулей; появляется вместе с первым внешним вызовом, не заранее |

**Не заводим** `utils.py`, `constants.py`, `helpers.py` «на всякий случай»: константа живёт рядом с тем, что её использует, или в `StrEnum` в `schemas.py`.

## Импорты между модулями

Другие модули импортируют **только `public.py`**, никогда `service`, `repository` или `schemas` чужого модуля. Импорт — явным именем модуля:

```python
from delivery import public as delivery

delivery.stats(db, now)
```

Функции `public.py` тонкие и сами собирают сервис: чужой модуль не зависит от устройства чужих классов. `from x import *` и глубокие пути в чужие модули запрещены. Границы новых модулей сторожит import-linter (`pyproject.toml`, `[tool.importlinter]`): слои `overview` → `delivery` → `conversations` → `research` → `companies` → `refusals | backup` → `core` (`refusals` и `backup` зовут все, друг друга не знают), чужой модуль — только через `public` (и для песочницы), песочница модулям недоступна, журнал `core.activity` пишут только `backup` и `delivery`, читает `overview`. Новый модуль вписывается в слои и получает свой контракт `protected` тем же PR. Миграции — не пакет, их сторожит `core/tests/test_import_graph.py`.

## Pydantic

- Встроенные валидаторы вместо ручных: `Field(min_length=, max_length=, ge=, pattern=)`, `AnyUrl`, `StrEnum`. Ограничения совпадают с `CHECK` в схеме базы.
- Не противоречь себе: `Field(ge=1, default=None)` — ошибка. Либо обязательное `Field(ge=1)`, либо `int | None = Field(default=None, ge=1)`.
- Нормализация входа (Postel's Law) — валидатором схемы: обрезка пробелов, телефон в каноническую форму, домен в нижний регистр, ник Instagram без `@`.
- Сериализация — `@field_serializer` / `Annotated[T, PlainSerializer(...)]`, не `json_encoders`. Время — ISO 8601 с таймзоной.
- Лишние поля во входе игнорируются (поведение по умолчанию), `extra="forbid"` не ставим.
- **Общая база схем** — один `class Schema(BaseModel)` с общим `model_config` и типом `Timestamp` (только с таймзоной). Все схемы запросов и ответов наследуют её — единственное наследование помимо исключений.
- **Ошибки — кодами, а не фразами.** Валидатор бросает `ValueError("errors.phoneInvalid")`, доменное исключение несёт `code`; наружу уходит `{"code": "errors.numberExists", "detail": "…"}`. Фронт ветвится по `code`, текст — для человека.

## Настройки

- `config.py` — единственное место чтения переменных окружения (`Settings(BaseSettings)`, читает `backend/.env`). `os.environ` в коде модулей не используется.
- То, что меняет оператор (сегменты, размер партии, модель, веса, окна, лимиты), — настройки модуля в базе, правятся на странице «Настройки». Новых `config.toml` не заводим.
- То, что защищает от капчи и бана (темп сети по хостам, число потоков, ретраи, адреса источников), — константы в коде модуля.
- Никаких значений по умолчанию для секретов.

## Зависимости

- Только `Annotated`-форма; алиасы объявляются рядом с зависимостью:

```python
Db = Annotated[sqlite3.Connection, Depends(get_db)]
ThreadDep = Annotated[Thread, Depends(valid_thread_id)]
DeliveryServiceDep = Annotated[DeliveryService, Depends(get_delivery_service)]
```

- **Зависимость проверяет, а не просто внедряет:** `valid_thread_id` загружает тред или бросает `NotFound` (404). Можно ли действие — решает сервис.
- Сервис получает зависимости в конструкторе (соединение, транспорт, модель, конфиг) и никогда не создаёт клиентов сам. Сборка — в `dependencies.py` для запроса и в `main.py` для фоновых задач.
- Время — параметром `now`; читает его одна функция (`clock.now()`) на границе: в роуте или в тике.
- Одинаковое имя параметра пути во всех роутах, где нужна общая зависимость (`thread_id`, `company_id`).

## Комментарии и docstring

- **Язык в новом коде — английский:** комментарии, docstring, сообщения для разработчика. Документация (`*.md`, спеки, ADR), коммиты и тексты для оператора — на русском. Старые русские комментарии специально не переводим: они уходят вместе с переписанным файлом.
- **Формат — PEP 257 + Google style.** Первая строка — резюме: у функции в повелительном наклонении (`Return…`, `Queue…`), у класса — описание. Дальше при необходимости `Raises:`, `Returns:` (когда смысл не виден из типа). `Args:` не пишем — типы в сигнатуре.
- **О чём писать:** зачем и какой контракт — побочные эффекты, что бросает и когда. Реализацию не пересказываем. Имя и сигнатура всё говорят — docstring не нужен; плохое имя лучше переименовать, чем объяснять.
- **Обязательно:** функции `public.py`, методы сервисов, Protocol-границы.
- **Не пишем:** у тестов (контракт — в имени теста) и у роутов — их описание в `summary=` декоратора.
- **Комментарий объясняет «почему»**, а не «что».

## Ядро (`core/`)

Общее без бизнес-логики; не импортирует ни одного модуля предметной области (сторожит import-linter).

| Файл | Что даёт |
|---|---|
| `db.py` | `connect(path)`, зависимости запроса `Db` (база момента, `paths.state_db()`) и `ProductionDb` (боевая база на запись, и в песочнице — её берут `companies` и `research`), `migrate(path)` / `downgrade(path, revision)` |
| `operator_settings.py` | `load(db, module, Schema)` и `save(db, module, values)` — настройки оператора (ADR 0003); `saved_section(db, module)` — раздел как сохранён, для правила, которого `load` не выражает (режим автопилота: неизвестное — `off`) |
| `errors.py` | `DomainError` (`code`, `status_code`) и обработчик `{code, detail}`; подключён в `main.py` |
| `schemas.py` | общая база `Schema` (обрезка пробелов) и `Timestamp` (только с зоной, хранится в UTC); схемы ответа модели наследуют не её, а `llm_schema.LLMSchema` |
| `pages.py` | адаптер сбора: `Pages` (Protocol, `get(url, *, cookies=None, headers=None)` — страница хранится по одному адресу), `ScraplingPages`, `FakePages` (пишет `requested` и `cookies`), `FetchError` и наследники (`HttpStatusError`, `BotCheckError`, `CertificateError` — негодный сертификат, для отката сайта на `http://`) |
| `model.py` | адаптер модели: `Model` (Protocol), `OpenRouterModel` (`temperature` в конструкторе, по умолчанию 0), `FakeModel`, `ModelError`, `ModelKeyMissingError`; `openrouter_client(api_key)` — клиент SDK для `ChatOpenRouter(client=...)` с общим сроком запроса |
| `phones.py` | каноническая форма телефона: `canonical(raw)` → `+7XXXXXXXXXX` без `+`, с `+` — 10–15 цифр как набраны, иначе `ValueError("errors.phoneInvalid")`; `PHONE` — форма телефона, `WHATSAPP_LINK` — номер из ссылки `wa.me`/`api.whatsapp.com` |
| `whatsapp.py` | адаптер WhatsApp: `WhatsApp` (Protocol: `send`, `check`, `pair`, `qr`, `health`), `NodeWhatsApp` (синхронный `httpx.Client` к Node-сервису, один на процесс — `app.state.whatsapp` в `main.py`; `base_url` — куда он шлёт, его проверяет песочница), `FakeWhatsApp` (пишет `sends` и `checks`; `sessions`, `sent`, `has_whatsapp`, `error` меняются по ходу теста), `Sent`, `TransportError` (исход отправки неизвестен) и `SessionLoggedOutError` (`TransportError` и `DomainError`: 409 `errors.sessionLoggedOut`) |
| `activity.py` | журнал фоновой работы: `Journal(path)` (`path` — функция: прогон песочницы меняет базу на живом процессе; в сборщике — `Journal(paths.state_db)`, один на процесс, `app.state.journal`), `record`/`record_quietly`/`record_crash` — своим соединением вне транзакции вызывающего, повтор последней строки — `repeats`; `recent`, `workers`, `last_at(actor)` — пульс, `prune` — ретенция 14 дней; зависимость роута `JournalDep` |
| `contacts.py` | каноническая форма контакта: `canonical(raw)` — телефон и ссылка WhatsApp на него → телефон, остальное — без пробелов по краям и в нижнем регистре; пустой, короче трёх символов или кривой телефон — `ValueError("errors.handleInvalid")` |

- **Настройки модуля** — Pydantic-схема с умолчаниями у каждого поля. `load` накладывает сохранённое на умолчания, неизвестные ключи игнорирует, значение, которое схема больше не принимает, заменяет умолчанием с предупреждением в логе. Кэша нет — правка действует со следующего вызова. `save` пишет раздел целиком и не коммитит: транзакцию держит сервис модуля.
- **`ScraplingPages(paths.PAGES, now=clock.now)`** — один на процесс, собирается в сборщике приложения (`app.state.pages` в `main.py`; модули получают его зависимостью, как `companies.dependencies.get_pages`, в тестах — `dependency_overrides` с `FakePages`): темп принадлежит хосту, и два экземпляра удвоили бы его. Повторный запрос в сеть не ходит, страница проверки робота и не-200 не сохраняются, любой сбой сети и кривой адрес — `FetchError`. Темпы по хостам — константы `HOST_INTERVALS` в `pages.py`. Откат на `http://` при ошибке сертификата — забота вызывающего (сайты компаний), не адаптера.
- **`OpenRouterModel`** ретраит обрыв соединения и ответ мимо схемы (`TRANSPORT_RETRIES`), ретраи SDK выключены; каждый HTTP-запрос — не весь `answer()` с ретраями — ограничен общим сроком `CALL_DEADLINE_S` (180 с, `DeadlineTransport`; худший случай вызова — три срока, около 9 минут): таймаут httpx — пауза между байтами, а OpenRouter держит соединение пробелами (#27). Новый клиент `ChatOpenRouter` собирается только через `openrouter_client`; всё, что не дало валидного ответа, — `ModelError` с одним именем класса ошибки (текст SDK цитирует данные лида). `ModelError` и `FetchError` — не `DomainError`: сервис решает, что с ними делать, иначе роут ответит 500. Кэша ответов нет: запись об оплаченном вызове — досье. Адаптеры синхронные и блокируют поток.
- **Fake-реализации** лежат в `core`, а не в тестах: ими пользуются тесты всех модулей.

## База данных

- Одна база `backend/data/state.db`; путь знает только `paths.py` (`paths.state_db()` — с учётом прогона песочницы, `paths.PRODUCTION_STATE` — всегда боевая). Модуль, который в песочнице обязан видеть настоящие компании и досье (`companies`, `research`), берёт `ProductionDb`, остальные — `Db`; кто только читает боевую базу (`overview`, `conversations`), открывает её `sqlite_tools.connect_readonly`.
- Соединение — `core.db.connect(path)`: WAL, `foreign_keys=ON`, ожидание блокировки 10 с, `sqlite3.Row`. В роуте — зависимость `Db`: соединение на запрос, закрывается после ответа.
- Транзакция — `with db:` в сервисе. В стандартном режиме `sqlite3` её неявно начинает первый DML, поэтому «прочитал, потом записал» не защищён — смена статуса только условным `UPDATE … WHERE status = :from`.
- SQL — сырой, в `repository.py` модуля, параметрами `?`. ORM и SQLAlchemy Core в коде модулей не используются (ADR 0004).
- Тесты — настоящая база во временном файле: `core.db.migrate(tmp_path / "state.db")`.

## Async

- **Асинхронный код не пишем** (ADR 0005): роуты — обычный `def`, FastAPI исполняет их в пуле потоков; фоновые демоны — потоки с синхронным циклом и флагом остановки, а не `asyncio`-задачи; внешние вызовы — синхронными клиентами (`httpx.Client`). Адаптеры сбора и модели синхронные (scrapling, LangChain).
- Доставка синхронная с #37: транспорт — `httpx.Client`, три демона — потоки с общим `threading.Event` остановки (`delivery.public.start`, рядом с `backup.loop`), вебхук — `def`. Очереди джоб и SSE больше нет (#38): `async` остался только у lifespan сборщика.

## Миграции

- Схема новых модулей — одна история Alembic в `backend/migrations/` (ADR 0004); `threads`, `messages` и `outreach_runs` переехали в неё ревизией `0005` (#36), она же убрала представление `suppression`; `outbox` и `numbers` — ревизией `0006` (#37: `CHECK` статусов, вида и автора строки); журнал `activity` — ревизией `0007` (#38), она же удалила старые `jobs` и `llm_answers`. Вне Alembic таблиц нет, кроме меты прогона песочницы (`sandbox_meta`).
- Ревизия, забирающая таблицу у старого владельца, в `downgrade` отдаёт её в старой форме с данными (`0005`): откат не имеет права терять невосстановимый слой. Поэтому `downgrade base` оставляет `threads` и `messages` в форме до `0005`, `outbox` и `numbers` — в форме до `0006`, `activity` — в форме до `0007` (и пустые `jobs` с `llm_answers`).
- Новая ревизия: `uv run alembic revision -m "<что меняется>" --rev-id 0002` (следующий номер после `uv run alembic heads`) → файл `migrations/versions/<дата>_<slug>.py`, `down_revision` проставится текущей головой.
- Операции — `op.*`, изменение таблицы — `with op.batch_alter_table(...)`: SQLite меняет таблицу только пересозданием. `downgrade` пишется всегда.
- Каждая ревизия идёт своей транзакцией (`migrations/env.py`): упавшая откатывается целиком. Внешние ключи на время миграции выключены — пересоздание таблицы иначе каскадно удалило бы дочерние строки.
- Применяются программно: при старте приложения (`main.py::prepare_database`, боевая база и база прогона) и при создании базы прогона песочницы. Отдельного шага деплоя нет.
- Миграцию одновременно добавляет один кодер. Перед пушем — свежий `main` и `uv run alembic heads`: голова одна.
- Тест модуля с новой таблицей проверяет цикл upgrade → downgrade → upgrade (образец — `core/tests/test_db.py`).
- Пересоздание таблицы в batch-режиме теряет её триггеры: ревизия, которая пересоздаёт `refusals`, создаёт заново `refusals_never_delete`, `refusals_never_update` и `refusals_keep_the_first` (`0002`), иначе тест схемы модуля упадёт.

## Фоновые задачи

- `BackgroundTasks` — только для коротких необязательных дел после ответа. Задача умирает вместе с процессом и не ретраится — ничего, что нельзя потерять. Исключения — сбор сегментов `companies` и партия `research` (минуты): состояние сбора — строка `segments`, партии — `batches` и `batch_companies`; старт приложения возвращает «собирается» в «не собран», а идущую партию помечает прерванной (её доделывает следующий запуск), так что потеря задачи стоит одного повторного запуска.
- Всё, что нельзя потерять, — строка состояния в таблице модуля и шаг тика, а не задача в памяти: очередь `outbox`, срок касания `threads.next_touch_at`.
- Демон не работает молча: исход каждого тика — запись в журнал (`core.activity.Journal`, приходит параметром).

## Тесты

- **Сначала тест, потом код (TDD).** Каждое поведение начинается с падающего теста, затем минимальный код до зелёного, затем рефакторинг под зелёными тестами.
- HTTP-шов — `httpx.AsyncClient` + `ASGITransport(app=app)` или `TestClient`.
- **Базу не мокаем:** настоящая база во временном файле со схемой, которую создают владельцы таблиц.
- `app.dependency_overrides` и Fake-реализации — только для внешних границ: модель (OpenRouter), транспорт WhatsApp (Node), сетевой сбор (scrapling). Тесты в сеть не ходят.
- Часы подменяем там, где их читают, — одной функцией; `now` дальше идёт параметром.
- Числа в тестах разбора — свойства эталонных страниц из `fixtures/`; расхождение значит, что поехал разбор.

## Логи

- Логгер модуля — `log = logging.getLogger(__name__)`. Никаких `print`, `logging.basicConfig`, своих хендлеров: формат задаёт `logging_setup.py`.
- **В лог — идентификаторы, а не данные.** Телефоны, тексты сообщений, тела запросов и ключи не логируем. Тред называется `company_id` (#36): номер лида — его `channel`, и в лог он не идёт.
- Уровни: `error` — надо разбираться человеку, `warning` — деградация без ошибки для оператора, `info` — редкие значимые события.
- Необработанное исключение уже попадает в лог — не ловим его, чтобы залогировать. `log.exception` — только когда ошибку обработали и работа продолжается.

## Документация API

Каждый роут объявляет `status_code`, тип ответа, `summary`, `tags` и ошибки в `responses=`. Тип ответа задаём **одним** способом: аннотацией возврата или `response_model`, не обоими.

## Команды

```bash
uv sync                                   # зависимости (uv.lock коммитится)
uv run pytest                             # все тесты, без сети
uv run pytest delivery/tests/test_domain.py  # один раздел — одним файлом
uv run python main.py                     # FastAPI, порт 8787
uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run lint-imports && uv run pytest  # полная проверка
```

Охват `ruff`, `mypy` (strict) и `import-linter` — новый код: `core`, `refusals`, `companies`, `research`, `conversations`, `delivery`, `backup`, `overview`, `sandbox`, `migrations` и сборщик `main.py` (`[tool.ruff] include`, `[tool.mypy] files` в `pyproject.toml`). Прочие `backend/*.py` вне охвата; тесты модулей верхнего уровня — `backend/tests/`; новый модуль добавляется в охват тем же PR, что его заводит. У тестов mypy не требует аннотаций сигнатур, тела проверяет. Заглушка — только с кодом правила и причиной: `# noqa: BLE001`, `# type: ignore[arg-type]  # причина`.

## Анти-паттерны — проверяй в каждом диффе

| Анти-паттерн | Почему плохо | Как надо |
|---|---|---|
| `async def` в новом коде | Одна блокирующая операция внутри замораживает весь процесс (ADR 0005) | Обычный `def`, демон — поток |
| `json_encoders` в `ConfigDict` | Удалён в Pydantic v2 | `@field_serializer` |
| `Field(ge=1, default=None)` | Ограничение противоречит умолчанию | Обязательное или `X \| None` |
| `x: T = Depends(...)` | Устаревшая форма | `Annotated[T, Depends(...)]` |
| `except Exception` вокруг тела роута | Прячет баги, 500 превращается в 200 | Ловить конкретное, бросать доменное исключение |
| Импорт `service`/`repository`/`schemas` чужого модуля | Ломает границы модулей | Только `from x import public` |
| SQL к таблице чужого модуля | Скрытая связность модулей | Функция `public.py` владельца |
| Сеть или вызов модели внутри транзакции | Нарушает атомарность, держит блокировку записи | Сначала коммит, потом вызов; изменения наружу — after-commit |
| «Прочитал статус, потом записал» | Гонка между тиком и кнопкой оператора | `UPDATE … WHERE status = :from`, ноль строк — конфликт |
| Модульный шов `use()` или глобальная переменная с соединением | Скрытый синглтон, тесты зависят от порядка | Зависимость в конструктор или параметром |
| `T \| None` как признак ошибки | Проверка расползается по всем вызывающим | Доменное исключение |
| Мок базы в тесте | Расхождение с настоящей схемой | Временный файл базы |
| `response_model=X` и `return X(...)` одновременно | Двойная валидация | Один способ |
| `utils.py`, `helpers.py`, `BaseService` | Свалка и абстракции без причины | Код рядом с доменом (корневой `CLAUDE.md`) |
| `raise ValueError("Телефон неверный")` в валидаторе | Фронт вынужден ветвиться по тексту | `ValueError("errors.phoneInvalid")` |
| Схема от голого `BaseModel` | Разный формат времени в модулях | Наследовать общую `Schema` |
| `print()`, `logging.basicConfig`, свой хендлер логов | Мимо общего формата | `logging.getLogger(__name__)` |
| Телефон или текст сообщения в логе | Персональные данные в файлах логов | Логировать идентификатор |
| `datetime.now()` в сервисе или домене | Тест зависит от времени запуска, песочница не может сдвинуть часы | `clock.now()` на границе, дальше параметр `now` |
