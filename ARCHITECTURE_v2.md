# ARCHITECTURE v2 — Система №1 «Targeting & Enrichment»

**Дата:** 10 августа 2026
**Статус:** предложение, альтернатива [ARCHITECTURE.md](ARCHITECTURE.md)
**Смежные документы:** [BRD](docs/BRD.md) · [PRD](docs/PRD.md) · [TRD](docs/TRD.md)

Тот же продукт, те же источники, те же критерии приёмки. Другая конструкция:
рассчитанная на реальный масштаб v1, а не на масштаб, до которого система дойдёт
через год.

---

## TL;DR

- **SQLite в один файл** вместо Postgres с тремя схемами
- **Ноль классов**, восемь модулей функций
- **Ни очереди, ни воркеров, ни стадий** — их работу делает кэш
- **Две команды** вместо семи этапов пайплайна
- Сырьё — папка gzip-файлов, адресуемых по хэшу; переживает любую смену стека
- Расходы на модель падают с ~$95 до ~$10 без потери результата

Всё, что было содержательно найдено при разведке источников, сохраняется без
изменений. Меняется только обвязка вокруг этих находок.

## 1. Отправная точка — цифры

| Величина | Значение |
|---|---|
| Компаний в базе | 1 000–1 500 |
| Вакансий с полным текстом | ~2 000 |
| Сетевых запросов за всю v1 | ~15 000 |
| Объём сырья | ~2 ГБ HTML, ~400 МБ в gzip |
| Время полного сбора | ~1,5 часа в 8 потоков |
| Время полной пересборки БД из сырья | ~2 минуты |
| Потолок отправки | 50–60 сообщений в день, вручную |
| Арендаторов системы | 1 |
| Критерий готовности | 30 компаний, с которыми начата переписка |

Расклад 15 000 запросов: списки 2GIS ≈ 1 300, карточки филиалов ≈ 3 000,
списки и вакансии hh ≈ 2 000, сайты компаний, прошедших дешёвый фильтр ≈ 5 000,
SERP ≈ 2 100.

**Это не конвейер данных. Это таблица на полторы тысячи строк и папка HTML.**
Все решения ниже выводятся отсюда.

## 2. Ключевое решение: кэш вместо оркестратора

Каждый сетевой ответ и каждый ответ модели сохраняются на диск под именем
`sha256` от запроса. Из этого следует:

> **Повторный прогон всего пайплайна с нуля стоит ноль и занимает две минуты.**

А значит, исчезает причина существования очереди, воркеров, состояния стадии в
строке, `attempts`, `next_retry_at`, `last_error` и разделения на быструю и
медленную очереди. Вся эта машинерия нужна ровно для того, чтобы не переделывать
дорогую работу. Кэш уже не даёт её переделывать — оркестратор охраняет то, что не
нуждается в охране.

Восстановление после сбоя выглядит так: перезапустить. Прогон, упавший на 800-й
компании из 1 500, при следующем запуске пролетает первые 800 из кэша за секунды.

Второе следствие, более важное на практике: **`build.py` можно запускать пятьдесят
раз в день.** Парсер и веса скоринга правятся на живых данных без единого сетевого
запроса. Это ровно то, что PRD F9 описывает словами «нормализованный слой
пересобирается из неизменяемого сырья сколько угодно раз» — здесь оно выполняется
буквально, а не как обещание схемы.

## 3. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Python 3.13, `uv` | Единственная незаменимая причина — Scrapling: TLS-impersonation реально нужен для hh.kz |
| Сеть | `Fetcher` + `ThreadPoolExecutor(8)` | stdlib. 15 000 запросов — полтора часа. Async не нужен |
| Сырьё | `raw/<sha256>.html.gz` | Content-addressed, gzip даёт 5–8×. Вне БД: база остаётся маленькой, сырьё бэкапится отдельным `rsync` |
| БД | **SQLite, один файл `leads.db`** | В stdlib. Ноль установки, ноль сервера, файл копируется и версионируется |
| Кэш модели | `llm/<sha256(промпт)>.json` | Тот же механизм. Делает перестройку бесплатной |
| Витрина | `VIEW` + экспорт CSV | 30 строк оператор читает глазами |
| Конфиг | `config.toml` + `tomllib` | stdlib |
| Секреты | `.env`, читается `uv --env-file` | как сейчас |

### 3.1 Почему не Postgres

Postgres в v1 был выбран ради `to_tsvector('russian')` и `pg_trgm`. Проверим оба:

**Полнотекстовый поиск** идёт по 2 000 вакансий — это 10 МБ текста. Обычный
`LIKE '%продаж%'` отрабатывает за 50 мс. FTS5 в SQLite тоже доступен; русского
стемминга в нём нет, но префиксный запрос `продаж*` покрывает суффиксную флексию
русского языка, которой почти всё и исчерпывается.

```
# ponytail: LIKE-скан по 2000 вакансий. FTS5 при 50k+, Postgres to_tsvector при 500k+
#           или когда понадобится настоящий стемминг с леммами.
```

**Нечёткая склейка имён** — `difflib.SequenceMatcher` из stdlib по кандидатам,
суженным городом и первой буквой. На 1 500 записях это доли секунды.

Ни одна из двух причин на этом масштабе не работает. Postgres вернётся вместе со
вторым арендатором — см. §9.

## 4. Модель данных

Три схемы `raw` / `core` / `mart` схлопываются в три физически разные вещи:
`raw` — это папка на диске, `core` — таблицы, `mart` — `VIEW`.

```sql
-- индекс к папке raw/ : что скачано, куда приземлилось, когда
fetches(url TEXT PRIMARY KEY, sha TEXT, final_url TEXT, status INT, fetched_at TEXT)

-- 2GIS
orgs(branch_id TEXT PRIMARY KEY, org_id TEXT, name TEXT, org_name TEXT,
     branch_count INT, city TEXT, rubric_id TEXT, address TEXT,
     rating REAL, review_count INT)

contacts(branch_id TEXT, kind TEXT, handle TEXT, source_url TEXT,
         PRIMARY KEY (branch_id, kind, handle))   -- phone|email|site|instagram|whatsapp

-- hh.kz
vacancies(id TEXT PRIMARY KEY, employer TEXT, title TEXT, text TEXT,
          published_at TEXT, city TEXT, slug TEXT, url TEXT)

-- склейка
companies(company_id TEXT PRIMARY KEY, name_norm TEXT, domain TEXT,
          city TEXT, rubric_id TEXT, first_seen TEXT)

company_links(company_id TEXT, branch_id TEXT, rule TEXT, confidence REAL)

-- сигналы: события с датой, не флаги
signals(company_id TEXT, type TEXT, observed_at TEXT, weight REAL,
        quote TEXT, url TEXT)

-- юридический контур: не очищается никогда
suppression(handle TEXT PRIMARY KEY, added_at TEXT, reason TEXT)
```

Восемь таблиц. Ключевые решения модели данных из ARCHITECTURE.md §9.2
сохраняются полностью:

| Решение | Статус |
|---|---|
| Сырьё неизменяемо, `core` пересобирается из него | ✅ усилено: пересборка — это `DROP` и заново, две минуты |
| `signals` — события с датой, не флаги | ✅ без изменений |
| `segment_id` = id рубрики 2GIS | ✅ колонка `rubric_id` |
| Все каналы равноправны, `telegram` не порождается из телефона | ✅ таблица `contacts` плоская, по строке на канал |
| `channels.confidence` — число | ❌ убрано, см. §6.4 |
| `core.companies` глобальная (мультиарендность) | ⏸ отложено: арендатор один |

### 4.1 Пересборка целиком, а не миграциями

`build.py` делает `DROP TABLE` и наполняет заново. На 1 500 строках это две минуты,
и это отменяет весь класс проблем: миграции схемы, частично применённые изменения,
рассинхрон парсера и данных. Схема правится редактированием `schema.sql`.

```
# ponytail: полная пересборка. Инкрементальная — когда пересборка перевалит за 10 минут,
#           то есть примерно на 100k компаний.
```

## 5. Раскладка и запуск

```
config.toml     рубрики, города, slug'и hh, веса скоринга, чёрный список
schema.sql      восемь таблиц + витрина как VIEW

cache.py        get(url) -> html      | llm(prompt) -> dict     content-addressed
sources.py      четыре источника: 2GIS, hh, SERP, сайты — запрос + разбор
resolve.py      склейка дублей
enrich.py       regex-детекторы: CRM, пиксели, реклама, соцсети
classify.py     единственный вызов модели, только по топу
score.py        fit_score, intent_score — возвращают (число, разбивку)

collect.py      ходит в сеть, наполняет raw/ и fetches
build.py        чистая функция raw/ -> leads.db, ни одного сетевого запроса
report.py       leads.db -> leads.csv
check.py        ассерты на живых фикстурах из raw/
```

Двенадцать файлов, из них три — данные и конфиг.

```bash
python collect.py            # 1,5 часа, один раз
python build.py              # 2 минуты, сколько угодно раз
python report.py             # выгрузка топа
python check.py              # проверки, сеть не нужна
```

Разделение `collect` / `build` — главная структурная граница системы. Слева от неё
единственное, что нельзя восстановить: страница удаляется, вакансия закрывается.
Справа — то, что пересобирается бесплатно.

## 6. Решения по этапам

Семь стадий S1–S7 не исчезают как работа, но перестают быть сущностями системы:
они становятся функциями внутри `build.py`, вызываемыми по порядку.

### 6.1 Сбор — без изменений

Разведка источников августа 2026 сохраняется целиком. В частности —
**обнаружение молчаливой подмены**, главная содержательная находка проекта:

| Источник | Признак подмены | Реакция |
|---|---|---|
| 2GIS | `currentPage` не равно запрошенной странице | штатный конец пагинации, стоп на 60 |
| hh.kz | конечный URL после редиректов не содержит slug | отказ: оператор ввёл несуществующий slug |

Механизм обнаружения общий, реакция разная. Обе проверки не зависят ни от какого
стека и переносятся дословно.

### 6.2 Склейка дублей

Правила из ARCHITECTURE.md §9.3 без изменений: домен, телефон в E.164, БИН,
Instagram — точно; похожее имя в пределах города — нечётко, с ручной проверкой.
Меняется реализация: `difflib` из stdlib вместо `pg_trgm`, `phonenumbers` для E.164.
Модель здесь по-прежнему не нужна — правила точнее и дешевле.

### 6.3 Модель: объём вместо техники

Один вызов Haiku на компанию со structured output — решение верное. Спорен объём:
**1 500 компаний против 300, которым вы напишете в этом цикле.**

Что модель на самом деле добавляет к уже известному:

| Поле | Откуда берётся без модели |
|---|---|
| `industry` | рубрика 2GIS, она же `segment_id` |
| `size_est` | ниоткуда — недостижимо ни одним источником (TRD, открытый вопрос №5) |
| `has_sales_team` | вакансия менеджера по продажам — детерминированный факт |
| CRM, пиксели, реклама | regex по сырому HTML |
| сигналы из текста сайта и отзывов | **вот здесь модель нужна** |

Остаётся чтение текста сайта — и оно нужно только тем, до кого дойдёт очередь.
Классифицировать всю базу значит платить за понимание компаний, к которым
вернутся через полгода, когда промпт и парсер всё равно будут другими.

```
# ponytail: классификация только по топу отсева. Вся база — когда появится второй
#           клиент и обогащение начнёт окупаться повторным использованием.
```

Кэш ответов модели по хэшу промпта означает, что переделка `build.py` не стоит
ничего: платится только за компании, увиденные впервые.

### 6.4 Каналы: телефон первым, верификации нет

Правило v1: **есть телефон — лид готов.** 2GIS отдаёт телефон практически всегда,
cold calling в КЗ жив, один номер даёт и звонок, и WhatsApp. Email и Instagram —
бонус.

Отсюда убирается верификация каналов целиком. Работа email-верификаторов на `.kz`
— открытый вопрос №4 TRD, бенчмарков нет ни у одного вендора; строить этап вокруг
неизвестности, когда базовый канал и так покрыт, преждевременно.

`channels.confidence` тоже убирается: число нужно Системе №3, чтобы беречь здоровье
доменов. В v1 отправка ручная — человек смотрит на номер и звонит.

```
# ponytail: без верификации каналов. Вернуть вместе с автоматической отправкой,
#           одновременно с confidence — у них один потребитель.
```

### 6.5 Скоринг

Две функции, возвращающие `(score, breakdown)` — список сработавших сигналов с
весами. Объяснимость (PRD F17) обеспечивается разбивкой, а не отдельной сущностью.
Веса — словарь в начале `score.py`, откалиброванный после первых 30 ответов.

`intent_score = Σ(weight × exp(-days_since / half_life))` — одно выражение.

Обе оси считаются правилами, не моделью: лид придётся объяснять клиенту, а чёрный
ящик объяснить нельзя. Это решение из ARCHITECTURE.md §10 сохраняется полностью.

### 6.6 Выдача и граница с человеком

`report.py` отдаёт CSV на 30–50 строк с колонками: компания, канал, `why_now` с
цитатой и ссылкой, разбивка скоринга.

**Статус переписки живёт в таблице оператора, а не в базе.** Кто ответил, кому
перезвонить, что сказали — это работа человека, и электронная таблица подходит для
неё лучше любой схемы. В систему возвращается ровно одно: `suppression` — у неё
юридическая природа (закон РК №94-V) и она обязана быть надёжной.

Отсюда из модели данных исчезают `stage` и `priority`: они описывали состояние
процесса, которого в системе больше нет.

## 7. Классов — ноль

Ни у чего нет состояния, живущего дольше вызова: кэш — функция от URL, парсеры —
функции от HTML, скоринг — функция от строки, склейка — функция от таблицы.

Классы появятся в двух случаях, оба узнаваемы заранее:

| Триггер | Что появится |
|---|---|
| Первый браузерный источник (Instagram) | Сессия, профиль, `user_data_dir`, circuit breaker — состояние настоящее |
| Второй арендатор | Postgres, очередь, мультиарендность, `RawStore` / `Db` |

До этих двух моментов класс не даёт ничего, кроме `self.` перед константой.

## 9. Границы и путь наверх

Конструкция не переживёт трёх вещей:

| Не переживёт | Наступит когда | Что делать |
|---|---|---|
| Второй арендатор | появится платящий клиент | Postgres, `companies` глобальная, очередь |
| ~100 000 компаний | смена ICP или выход в РФ | Postgres, инкрементальная сборка, FTS |
| Ветвящиеся workflow | Система №3 с автоотправкой | тогда и только тогда — очередь со стадиями |

Ни одно из трёх в v1 не наступает: потолок 50–60 сообщений в день делает сто тысяч
компаний бессмысленными, а арендатор пока один и это автор проекта.

**Что делает ставку безопасной:** самый дорогой актив — папка `raw/` — не зависит
от стека вообще. Переезд SQLite → Postgres это один вечер и почти тот же SQL:
`build.py` просто пишет в другое соединение, а перекачивать не приходится ничего.
Данные, которые нельзя восстановить, лежат отдельно от решений, которые можно
пересмотреть.

## 10. Чем отличается от ARCHITECTURE.md

| Тема | ARCHITECTURE.md | v2 | Причина |
|---|---|---|---|
| Хранилище | Postgres, схемы `raw`/`core`/`mart` | SQLite, один файл | 1 500 строк; FTS и trgm на этом объёме не окупают сервер |
| Сырьё | `raw.fetches(payload jsonb)` | `raw/<sha>.html.gz` + индексная таблица | База остаётся лёгкой, сырьё бэкапится отдельно и переживает смену стека |
| Оркестрация | Postgres-очередь, воркеры, стадии, две очереди | нет | Кэш делает повторный прогон бесплатным — охранять нечего |
| Пайплайн | 7 стадий как сущности | 7 функций в `build.py` | Стадия имеет смысл, когда её можно перезапустить отдельно; здесь перезапускается всё |
| Коннекторы | 4 класса + единый контракт | 4 модуля функций | Состояния нет; контракт держится сигнатурой, а не абстракцией |
| Классы всего | ~12 | 0 | Ни у чего нет состояния дольше вызова |
| Модель | 1 500 компаний | топ-300 | Отрасль, размер и отдел продаж известны без модели |
| Верификация каналов | отдельный этап S7 | нет | Телефон из 2GIS не верифицируется; email на `.kz` — открытый вопрос |
| Витрина | `mart.lead_profiles` | `VIEW` + CSV | 30 строк читаются глазами |
| Статус переписки | `stage`, `priority` в БД | таблица оператора | Это работа человека |
| Браузерный пул | описан | нет файла | В v1 не используется |
| Бюджет | ~$105 | ~$15 | Следствие объёма классификации |

**Что сохранено дословно:** обнаружение молчаливой подмены, правила склейки,
`signals` как события с датой, скоринг правилами, `segment_id` = рубрика 2GIS,
неудаляемое сырьё, равноправие каналов, ручная отправка, `suppression`.

Разведка источников — самая ценная часть проделанной работы, и она не зависит от
обвязки. v2 меняет обвязку и не трогает находки.
