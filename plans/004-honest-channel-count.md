## Зачем это нужно

Две мелкие, но связанные неправды в выдаче — обе про правило F19 «лид без
рабочего канала в выдачу не попадает».

**Первая.** `report.available()` считает «сколько лидов вообще доступно» своим
SQL-запросом, а не теми же правилами, по которым выдача собирается на самом
деле. Он смотрит только на вид контакта и не вычитает отказы (F21). Список
отказов сегодня пуст, поэтому расхождения нет — но оно появится с первым же
отказом и будет расти. Число видно оператору в шапке интерфейса
(`frontend/app/page.tsx:66`) и задаёт пункт «все N» в выборе размера выдачи
(`frontend/app/page.tsx:95`), то есть оператор будет запрашивать больше лидов,
чем существует. Файл `report.py` сам объявляет принцип «логика F19/F21 не
дублируется, а импортируется» — `available()` единственное место, где он
нарушен.

**Вторая.** 13 телефонов из 2706 — короткие сервисные номера 2GIS (`1400`,
`3003`, `4545`, `5151`, `7788`, `349550` и подобные). Двое лидов из 995
получают такой номер как единственный канал связи, то есть формально F19
соблюдён, а фактически оператору нечего набрать. Отбраковка обязана быть
аккуратной: `88002500405` (бесплатная линия, 11 цифр) и `+77273398932,,,2405`
(номер с добавочным, 15 цифр) — рабочие каналы, и терять их нельзя.

Обе правки удаляют код, а не добавляют.

## Шаги

### Шаг 1: отбраковать короткие сервисные номера на границе F19

В `collector/report.py` добавь константу и проверку. Константу помести рядом с
`CHANNEL_PRIORITY` (строка 31), с объяснением:

```python
# Короче этого 2GIS отдаёт не телефон компании, а сервисный короткий номер
# (1400, 5151, 349550 — их в базе 13 из 2706). Порог именно по числу цифр, а не
# приведение к +7XXXXXXXXXX: бесплатная линия 8-800 (11 цифр) и номер с
# добавочным (15 цифр) оператору годятся, и терять их нельзя.
MIN_PHONE_DIGITS = 10
```

Затем в `best_channel()` добавь проверку достижимости. Нужная форма:

```python
def best_channel(channels, suppressed):
    """Первый канал из приоритетного списка, не попавший в suppression.

    Канал, по которому нельзя связаться, каналом не считается: F19 требует
    рабочего, а не любого.
    """
    for kind in CHANNEL_PRIORITY:
        for channel_kind, handle in channels:
            if channel_kind != kind or handle in suppressed:
                continue
            if not reachable(kind, handle):
                continue
            return kind, handle
    return None


def reachable(kind, handle):
    """Можно ли по этому каналу связаться. Почта проверяется только на непустоту."""
    if kind == "email":
        return bool(handle and "@" in handle)
    return len(re.sub(r"\D", "", handle or "")) >= MIN_PHONE_DIGITS
```

`dialable()` не трогай: она уже привела whatsapp-ссылку к номеру, и `reachable`
получает готовый номер.

### Шаг 2: заменить SQL в `available()` на тот же проход, что делает выдача

В `collector/report.py` замени тело `available()`. Нужная форма:

```python
def available(db):
    """Потолок выдачи: компании с intent и рабочим каналом, которым можно писать.

    Считается тем же проходом, что и сама выдача, а не отдельным запросом:
    отдельный запрос знал бы про вид контакта, но не про отказы (F21) и не про
    достижимость номера, и врал бы оператору тем сильнее, чем длиннее список
    отказов. Полный проход стоит сотые доли секунды на 1660 компаниях.
    """
    suppressed = {row[0] for row in db.execute("SELECT handle FROM suppression")}
    return sum(
        1 for row in candidates(db) if best_channel(row["channels"], suppressed)
    )
```

После этого константа `kinds` и SQL-запрос из старого тела удаляются целиком.

**Проверка**: `uv run report.py` → выход 0, печатает
`компаний с intent > 0: 1020, из них без рабочего канала: 27`
(1020 − 993 = 27; число 993 — это 995 минус двое, потерявшие единственный канал
на шаге 1: `Freedom Telecom` с номером `4000` и `PingOcean` с номером `349550`).

Если получилось другое число «без рабочего канала», сверься с расчётом:
`available()` обязан дать `993`. Проверить напрямую:

```

```

## Заметки на будущее
