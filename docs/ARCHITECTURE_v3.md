## TL;DR

- **Четыре независимых слоя ИИ-анализа** вместо одного большого вызова:
  отзывы 2GIS, внутренние страницы сайта, Instagram, синтез досье.
- **Каждый слой кэшируется своим ключом** в `state.llm_answers`: досбор одного
  отзыва не обесценивает оплаченные ответы остальных слоёв.
- **Досье — контракт с системой 2**: `summary`, `hooks` (2–5 зацепок с дословной
  цитатой и ссылкой), `pains` (≤4, по убыванию тяжести), `approach`, `sources`.
- **Веса сигналов остаются правилами** из `config.toml`; модель их не видит.
  «Доказательство утечки лидов» (жалоба клиента вслух) весит 5.0, инфраструктура
  (есть почти у всех) — 0.5.
- **Обрабатывается вся база**, а не топ-40: `top_n` удалён.
- **Главная защита от выдуманного факта** — `test_quote_is_verbatim`: цитата
  сигнала обязана стоять дословно в сырье.

## 1. Проблема, которую решаем

Замер на рабочей базе (1660 компаний, 1876 сигналов):

| признак | покрытие | вес до v3 |
|---|---|---|
| `ads_platform` | 64% от имеющих сайт | 3.0 |
| `inbound_widget` | 55% | 1.5 |
| `service_catalog` | — | 0.5 |
| `crm_widget` | 12% | 3.0 |
| `ig_*` | 11% базы | 1.5–3.0 |

Следствия: 39% компаний без единого сигнала; 266 компаний делят `intent_score =
4.4`; `profiles` заполнены у 40 из 1660; системе 2 нечем персонализировать
(`industry=None, why_now=None` для 1620 компаний).

Корень: сырьё — главная страница сайта и 12 подписей Instagram. По такому
материалу нечего анализировать даже человеку. v3 добавляет отзывы 2GIS
(78% покрытия — лучший источник), внутренние страницы сайта и комментарии
Instagram.

## 2. Послойный анализ вместо одного вызова

Ключ кэша — `sha256(модель + промпт)`. Если слить все источники в один промпт,
досбор одного отзыва меняет промпт целиком и обесценивает оплаченный ответ; один
упавший источник роняет всё досье.

При послойном анализе каждый источник кэшируется отдельно:

- новый отзыв переспрашивает слой отзывов, а не все четыре;
- новый источник добавляется без переплаты за старые;
- компания без сайта всё равно получает досье из отзывов.

Суммарный объём токенов тот же — текст один и тот же.

### Слои

| слой | операция | kind в `llm_answers` | покрытие |
|---|---|---|---|
| отзывы 2GIS | `analyze.reviews` | `reviews` | 1301 компания |
| сайт (главная + ≤6 внутренних) | `analyze.site` | `site` | 1088 компаний |
| Instagram (10 постов + комментарии + био) | `analyze.instagram` | `instagram` | 229 аккаунтов |
| синтез досье (по извлечённым фактам) | `analyze.dossier` | `dossier` | все 1660 |

`synthesize_dossier` работает только по извлечённым слоями фактам — ни одной
сырой страницы, промпт маленький. Компания без сайта и Instagram получает досье
из отзывов и карточки 2GIS: полного нуля не остаётся ни у кого.

### Судьба старых операций

`analyze.profile` → `analyze.dossier`; `analyze.ig_signals` → `analyze.instagram`.
Обе сняты из реестра операций вместе с наполнением `profiles`. Их оплаченные
ответы остаются в `llm_answers` — кэш ничего не теряет, просто перестаёт их
находить.

## 3. Досье — контракт с системой 2

Форма определяется одним вопросом: что нужно, чтобы написать первое сообщение в
WhatsApp, на которое ответят.

```
Dossier:
  summary    — чем занимается, 3-6 слов
  hooks      — 2-5 зацепок, по одной на ход переписки; каждая с ДОСЛОВНОЙ
               цитатой, ссылкой и источником (reviews|site|instagram)
  pains      — ≤4, от сильной к слабой; пустой список законен
  approach   — как заходить (позитивная инструкция, без запретов)
  decision_maker_hint — подсказка, к кому обращаться
  sources    — ровно те слои, что участвовали (против выдумывания «ваш сайт»
               у компании, у которой сайта нет)
  confidence — уверенность, 0..1
```

Решения формы:

- **`hooks` — список.** Writer ведёт тред: первому сообщению, follow-up и ответу
  на возражение нужен свой угол, повтор выдаёт шаблон.
- **`pains` — список с потолком 4 и порядком по тяжести.** Порядок и лимит
  закреплены кодом в `fill_dossiers` (сортировка по `SEVERITY_ORDER`, обрезка до
  4), а не только словом в промпте.
- **`approach` вместо `do_not_mention`.** Список запретов отвергнут: он дублирует
  `pains` в форме запрета и эксплуатирует слабость моделей к отрицаниям.
  Позитивная инструкция исполнима, запрет — нет.
- **`sources` — против выдумывания.** Писатель обязан знать, что сайта не видел
  (таких 572 из 1660).

Хранение — вычислимая таблица `dossiers_all` + view `dossiers`, как остальные
`*_all`. Невосстановимое здесь — ответы модели в `state.llm_answers`; пересборка
читает их через ATTACH и пишет только в `derived.db` («ни одна операция не пишет
в обе базы»).

## 4. Скоринг: веса-правила, модель не видит цену

Regex не выкидывается там, где объективно лучше модели (детерминированный поиск
`bitrix24` в разметке), но перестаёт определять порядок.

| сигнал | судьба | вес |
|---|---|---|
| `crm_widget` | остаётся regex | 3.0 |
| `ads_platform` | 3.0 → | **0.5** |
| `inbound_widget` | 1.5 → | **0.5** |
| `service_catalog` | удаляется | — |
| `reviews_missed_lead` | новый слой | **5.0** |
| `reviews_unanswered_complaint` | новый слой | **5.0** |
| `ig_unanswered_question` | новый слой | **4.0** |
| `site_hiring_sales` | новый слой | **3.0** |
| `ig_reach_declining` | арифметика | **3.0** |
| `ig_dormant` | арифметика | 3.0 |
| `site_no_pricing` | новый слой | **1.5** |

Обоснование не идеологическое: когда ответят первые 30 лидов, понадобится
поднять вес сработавшего сигнала — с весами в TOML это правка одной строки и
пересборка за секунды.

Модель делает то, чего regex не умеет: находит и формулирует сам факт. Regex
никогда не поймёт, что «звонила три раза, никто не берёт трубку» — это утечка
лида.

- Тип без веса — **ошибка сборки** (`emit` бросает `KeyError`), а не тихий 0.5.
- Один тип — один сигнал, от самого свежего подтверждённого доказательства
  (`newest_review_match`, по одному на тип на компанию).
- **Динамика охватов** — медиана лайков свежей пятёрки против старшей, а не
  среднее: один залетевший пост не создаёт ложный тренд. Для лент короче 6
  постов тренд не считается вовсе.

## 5. Сбор сырья

Все новые источники ложатся в `data/raw/` как обычные страницы
(`<sha1(url)>.html.gz` + сайдкар) — граница системы не двигается.

| источник | запрос | объём | риск |
|---|---|---|---|
| отзывы 2GIS | `public-api.reviews.2gis.com/2.0/branches/{id}/reviews` | 1458 запросов, ~4 мин | недокументированный API, ключ в `config.toml` |
| внутренние страницы сайта | выбор с главной по словарю `config.toml` | ≤6 страниц на сайт | нет |
| комментарии Instagram | `media/{pk}/comments/` — только для постов с `comment_count > 0` | 1027 запросов | личная сессия, ~1.7ч |
| профиль Instagram | `users/{pk}/info/` — числовой pk из ленты | 255 | часть аккаунтов откажет |

- **Словарь ссылок сайта** применяется и к тексту ссылки, и к её адресу: у
  .kz-сайтов слоги латиницей (`/services/`), а словарь на русском — по одному
  адресу обход находил бы ноль страниц.
- **`IG_POST_COUNT = 12` в сборе не меняется** (count входит в URL → в ключ
  кэша). Лимит 10 постов применяется на анализе.
- **`parse_ig_post` хранит `pk`** — без него комментарии не запросить.

## 6. Проверки

| тест | что проверяет |
|---|---|
| `test_parsers` | разбор отзывов, комментариев, ссылок — на эталонных `fixtures/` |
| `test_signals` | новые типы в `config.toml`; тип без веса — ошибка сборки |
| `test_quote_is_verbatim` | **главный**: цитата каждого AI-сигнала стоит дословно в сырье |
| `test_dossiers` | hooks с цитатой/ссылкой; pains ≤4 и по тяжести; sources — те слои |
| `writer/tests/test_leads` | отбор по запросу с `dossiers` |
| `test_rebuild_import_graph_has_no_network` | пересборка не тянет сеть транзитивно |

`fixtures/` пополняется по одной эталонной странице на каждый новый разбор
(отзывы, комментарии, профиль, главная со ссылками) — числа в тестах — свойства
именно этих файлов.

## 7. Граница с системой 2

`writer/leads_source.py` читает `dossiers` вместо `profiles`:

```
было:  p.industry, p.why_now, p.quote ... LEFT JOIN profiles p USING (company_id)
стало: d.summary, d.hooks, d.pains, d.approach, d.sources
       ... LEFT JOIN dossiers d USING (company_id)
```

Seed системы 2 несёт `dossier` (summary/hooks/pains/approach/sources) + `signals`.
Полная перепись промпта системы 2 под богатое досье — отдельная задача за
границей системы 1.

## 8. Риски

- **Instagram-бан.** Снижен вдвое правилом «только посты с комментариями», не
  устранён: сессия личная, пауза 6с, проверка живости.
- **API отзывов 2GIS недокументировано.** Ключ могут сменить, лимиты ввести.
  Собранное в `raw/` останется навсегда.
- **`raw/` вырастет** с ~464 МБ до ~1.5 ГБ. Папка не в git, бэкапится отдельно.
- **Промпт системы 2 не переписан** — досье богатое, письма прежние, пока не
  сделана следующая задача.

## 9. Что не делаем

- Сторис Instagram — живут 24 часа, требуют ежедневного мониторинга.
- Полный обход сайта по `sitemap.xml` — 30 тыс. страниц, большая часть —
  карточки товаров и пагинация блога.
- Инкрементальную пересборку — полный прогон на 1660 компаниях занимает секунды.
- Оценку готовности лида моделью — веса остаются правилами (§4).
