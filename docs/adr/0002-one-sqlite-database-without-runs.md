# Одна база SQLite без прогонов

Раньше баз было две: `derived.db` пересобиралась целиком «прогонами» (`run_id`, таблицы `*_all`, `activate_run`, представления), `state.db` хранила невосстановимое. Прогоны существовали, чтобы пересобирать всю выдачу разом из сырья; при исследовании по одной компании (ADR 0001) пересобирать разом нечего. Решили: база одна, компания и её досье пишутся сразу, повторное исследование добавляет новую версию досье. Скачанные страницы по-прежнему сохраняются файлами — разбор можно поправить и перезапустить для компании без похода в сеть.

## Considered Options

- **Postgres с async SQLAlchemy и Alembic.** Даёт хостинг с управляемыми бэкапами и задел под второго пользователя, но требует Docker для локального запуска, миграций и асинхронного кода уже в первом цикле. Отложен до второго пользователя или хостинга: запросы спрятаны в `repository.py`, переезд затронет репозитории и схему.

## Consequences

- Пропадает откат всей выдачи одним действием на прошлый прогон.
- Данные в ноябре 2026 потерялись из-за отсутствия бэкапа, а не из-за SQLite; надёжность даёт автоматический бэкап (#8), а не смена базы.
