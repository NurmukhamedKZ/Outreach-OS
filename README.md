# Targeting & Enrichment, Казахстан

Документы: [BRD](docs/BRD.md) · [PRD](docs/PRD.md) · [TRD](docs/TRD.md) · [SPEC](docs/SPEC.md) ·
[ARCHITECTURE](docs/ARCHITECTURE.md) · [ARCHITECTURE_v2](docs/ARCHITECTURE_v2.md)

Все три системы физически лежат в `backend/` (`backend/collector/`,
`backend/writer/`, `backend/sender/`) под одним venv и одним `backend/main.py`;
ниже относительные имена `collector/`, `writer/`, `sender/` всегда
подразумевают путь внутри `backend/`.

## Команды

Продуктовый дашборд — во `frontend/`. Сбор, анализ и пересборка — операции
воркера (`collector/services/pipeline/`), а не скрипты: из консоли они
ставятся джобами через веб, из тестов — вызовом функции с RunContext. Логика
и сеть в `services/`, схема с запросами в `db/`, сырьё — в `data/raw/`, две
базы — в `data/`. Команды ниже запускаются из `backend/`.

```bash
uv run pytest                            # тесты обеих систем, без сети
cd writer && uv run pytest tests/        # тесты системы 2, тот же venv
```

Разведка источника вручную — операция `probe` из консоли
(`services/pipeline/probe.py`): пробы ходят в сеть и читают config.toml.

Модель зовётся через OpenRouter: ключ `OPENROUTER_API_KEY` в `.env`, имя модели —
в `config.toml` `[llm].model`. Ответы кэшируются в `state.llm_answers` по
`(kind, subject, model, prompt)`, поэтому пересборка не стоит ни цента.

Сбор (`collect.*`) ходит в сеть и наполняет `data/raw/`. Ленте инстаграма нужны
куки — `uv run -m ig.login` разово.

`rebuild` — граница системы: слева от неё то, что нельзя восстановить (`data/raw/`
и `state.db`), справа то, что пересобирается бесплатно прогонами. Поэтому rebuild
не импортирует ни `fetch`, ни `scrapling`, и тест графа импортов это проверяет.
Прогон пишет все `*_all` таблицы и публикует их одним `activate_run()` в конце —
`api.py` читает старую выдачу всё время, пока идёт пересборка, а откат —
`activate_run(старый run_id)`.

## Веб-дашборд

Два процесса. Бэкенд читает `derived.db`/`state.db`, фронтенд проксирует `/api/*`
на него, так что браузеру нужен только порт 3000.

```bash
uv run --env-file collector/.env python main.py               # FastAPI, все три системы (из backend/)
cd frontend && npm run dev                                    # Next.js -> http://localhost:3000
```

`python -m uvicorn`, а не голый `uvicorn`: без `-m` uv берёт системный бинарарь
с чужим python и падает на импорте зависимостей.

Дашборд — сайдбар с тремя системами и страница на каждую: «Обзор» (счётчики и
живые процессы), «Сбор лидов» (выдача и карточка), «Персонализация» (инбокс
тредов и черновики), «Отправка» (закрыта, «скоро»). Запуск — продуктовыми
кнопками `POST /api/pipeline/{kind}` и одиночными `POST /api/operations/{name}`:
джоба встаёт в очередь (`state.jobs`), воркер исполняет её шаги в том же процессе
через `asyncio.to_thread`, а прогресс, шаги и живой лог приходят в браузер по
SSE `GET /api/events`. Исполнение одно за раз (`rebuild` пересобирает derived
прогоном), очередь честная: ставить можно несколько. Хвост лога добирается
`GET /api/jobs/{id}?offset=`. История прогонов и откат выдачи — `GET /api/runs`,
`POST /api/runs/{id}/activate`.

Что делает оператор: смотрит лид, читает `why_now` с цитатой с сайта компании,
копирует канал, пишет руками. Статус переписки ведёт система 2 в `state.db`;
в систему 1 возвращается только отказ (suppression).

## `fixtures/` — эталонные страницы

По одной на каждый разбор в `services/sources.py`: рубрика и карточка филиала 2GIS.
Сняты из `raw/` и, в отличие от него, лежат в git — иначе проверка разбора не
работала бы на чистом клоне.

Числа в `test_parsers` — свойства именно этих файлов, а не «примерно столько»:
страница в git не меняется, поэтому расхождение означает, что поехал разбор, а не
что источник поменял вёрстку. Правятся только вместе с фикстурой.

## `raw/` — слой сырья

Скачанные страницы: `<sha1(url)>.html.gz` и сайдкар `<sha1(url)>.json`
(`url`, `final_url`, `status`, `fetched_at`).

**Папка невосстановима.** Вакансия закрывается, страница удаляется — перекачать
собранное нельзя. В git она не хранится (на целевом объёме это гигабайты), поэтому
**бэкапится отдельно**, вне репозитория.

Не удалять. Не чистить как кэш. `final_url` из сайдкара — единственный способ
поймать молчаливую подмену страницы источником.

## Две базы

- **`data/derived.db`** — пересобираемое: `runs`, `current_run`, `*_all` + view
  (`db/schema.sql`, DERIVED-часть). Собирается прогонами `rebuild.run`.
- **`data/state.db`** — невосстановимое: отказы (`state.suppression`), очередь
  джобов (`state.jobs`), переписка системы 2, ответы модели (`state.llm_answers`).
  Схема через `CREATE TABLE IF NOT EXISTS`, `DROP` запрещён.

## suppression — юридический контур

Кому больше не писать (закон РК №94-V, PRD F21). Источник истины — таблица
`state.suppression` в невосстановимой базе, а не файл: пересборка её не
затрагивает. Список никогда не очищается; выгрузка — `GET
/api/suppression/export.csv` по требованию.

Пополняется из веб-интерфейса (`POST /api/suppression`) или руками; `export` и
API проверяют **до** выдачи, а не после.
